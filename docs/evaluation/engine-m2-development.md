# M2 감성 사전 개발 기록

2026-09-07 갱신. Old v1 reserve에서 분리한 공개 development 10,000건의 반복 측정이다.
독립 최종 성능을 뜻하지 않는다. 목표 Accuracy 0.67은 아직 달성하지 못했다.
**Phase 2는 Accuracy 60.61%에서 종료했다.** 추가 사전·규칙 개선을 중단하고
현재 M2-L 한 후보를 동결했다. 개발 중 selection/final 데이터는 생성하거나 열지 않았다.
사용자의 명시적 지시로 미달한 개발 Gate를 기록한 채 direct final 평가 단계로 넘어간다.
후보·기준 후보·평가 코드 동결 근거는 [동결 기록](engine-m2-freeze.json)에 있다.

## 데이터와 평가 경계

기준 커밋은 `0c25c75145f308a572083702f51f3e238169bb42`다.
기존 v1/v2 평가 모듈·프로토콜·노출 레지스터는 수정하지 않았다. 별도 workset 준비,
라벨 없는 mining, development 실행 스크립트만 추가하고 기존 snapshot/worker/metrics를 재사용했다.
변경 전후 평가 인프라의 SHA-256은 [측정 기록](engine-m2-development-results.json)에 있다.

기존 release의 manifest/groups 해시와 원본 파일 해시를 검증했다. `groups.jsonl`에서
reserve 그룹만 JSON으로 해석하고, 다른 분할은 그룹 ID·split 메타데이터만 검사했다.
원본 파일은 해시만 계산했다. 기존 selection/final 입력·gold 파일은 접근하지 않았다.

분할은 라벨을 사용하지 않았다. Development 구성은 positive 4,971건, negative 5,029건이다.
Old non-reserve 그룹과 workset의 중복, mining/development/untouched 간 그룹 중복은 0이다.
추가로 mining/development 원문만 사용해 정규화 완전 중복과 길이 20자 이상 문장의
5-shingle Jaccard ≥ 0.85를 완전 후보 탐색으로 검사했으며 중복 쌍은 0이었다.
기존 reserve 그룹은 LSH로 구성되었으므로, 이 확인을 미래 holdout 전체의 독립성 보장으로
확대하지 않는다. 향후 별도 단계에서 새로운 노출 감사를 해야 한다.

Workset은 `artifacts/benchmark/m2-workset/`에 있고 각 입력·배정 파일의 해시,
원본 및 old v1 계보는 측정 기록에 보존했다. 원문은 Git에 추가하지 않았다.

## 라벨 없는 감사와 구현

Miner는 모든 행의 `{id, text}` 스키마를 분석 전에 검증한다. 미매칭 형태소·POS와
어절을 독립 그룹 빈도, 문서 빈도, 어휘 순으로 정렬한다. 라벨 비율이나 극성 점수는
계산하지 않으며 사전에 자동으로 극성을 쓰지 않는다. 기존 M의 mining 미매칭은
15,786건, 2차 배치 뒤에는 10,579건이었다. 두 번 모두 분석 오류는 780건이다.

추가 항목은 독립적인 평가 의미, 관측된 형태소 key, 다의성, 포함·제외 이유를 감사했다.
Mining의 여러 그룹에서 관측되거나 표준적인 평가 어휘로 독립 설명 가능한 항목을
채택했다. 검수는 AI 보조이며 독립적인 사람의 검수는 아니다.

| 배치 | 추가 원본 어휘 | 주요 내용 |
|---|---:|---|
| 1 | 114 | `별루`, `비추`, `맛없다`, `부러지다` 등 구어·결함·불편 어휘와 표기형 |
| 2 | 121 | 평가 명사·하다 활용형, `안되다`, `성의 없다` 등 어휘적 구성 |
| 3 | 81 | 부정 표현 우선 감사: `먹통`, `불호`, `엉망진창`, `뒤틀리다`와 활용·구어형 |

기존 어휘의 점수는 조정하지 않았다. 신규 점수는 의미 강도 ±1/±2/±3으로 측정 전에
정했으며 가중치·임계값 탐색, 문장별 예외, ID·정답 기반 규칙을 추가하지 않았다.
`냄새`, `반품`, `환불`, 크기·길이 같은 중립적 설명에는 일괄 극성을 부여하지 않았다.
`그럭저럭`·`쏘쏘`도 negative로 강제하지 않았다.

매칭은 띄어쓰기 없는 명사 뒤의 독립 술어를 허용하도록 품사 경계를 보강했다.
명사 복합어 일부나 접두사 내부 매칭은 계속 차단한다. 컴파일러의 문맥 alias에는
검증된 `token_start`를 허용해 문맥에 따라 달라지는 POS를 명시할 수 있게 했다.
실제 분석 토큰과 alias가 정확히 일치해야 하며 충돌·감사·최소 개수·재현성 검증은 유지한다.

`비추/VV`, `안/VV`, `사기/NNG`, `쓰레기/NNG`처럼 다른 뜻과 겹치는 단독 key는
확장하지 않았다. 감성 용법에 필요한 완전한 서술 형태만 보존하고 빛·포옹·사기(士氣)·
쓰레기 봉투 등의 반례를 검증했다. 원문 정규화, 어간 추측, 근사 offset 복원은 추가하지 않았다.

최종 검토에서는 자동 생성된 조사형 중 문법적 근거가 부족하고 mining에서도 지지되지
않은 286개 variant를 제거했다. `행복가`, `아름답다이` 등이 해당한다. 이는 라벨·예측을
사용하지 않은 원형·조사 문법 감사이며, 이전 배치 기록을 덮어쓰지 않고 별도 정리 이력으로 남겼다.

현재 원본 613개에서 병합·제외 후 compiled 대표 어휘는 565개다.
Positive 207개, negative 358개, customer_support 73개이며 충돌은 0개다.
항목별 근거는 `data/lexicon_annotations.json`, 배치·정리 이력은
`data/lexicon_provenance.json`에 있다.

## 기존 어휘 매칭 보강과 미매칭 재집계

60.35% 체크포인트 이후에는 대표 어휘와 기존 점수를 고정했다. 먼저 제시된
`좋아서`, `배송빠르고`, `맛없고`, `괜찮아요`, `이뻐요`가 이미 매칭됨을 확인했다.
실제 누락을 재현한 뒤 다음 두 체크포인트를 각각 고정 development에서 측정했다.

1. 매칭 보강 1: 명사 뒤에 붙은 완전한 `명사+이/VCP` 서술 key를 허용했다.
   `물건불량이고` 등을 인식하지만 `불만접수입니다`·`행복주택입니다`의 내부 명사는
   계속 차단한다. 기존 어휘의 파생 술어·활용형 8개와 POS alias 4개를 검수해
   `걱정했는데`, `누락되어`, `괜찮아`, `구려요.` 같은 누락을 보강했다.
2. 매칭 보강 2: 아래 집계에서 POS 차이와 명사·접미사 경계 두 원인만 선택했다.
   기존 어휘의 활용형 11개와 alias 2개를 보강했다. `비리고`는 `비리/NNG+이/VCP`,
   `대만족입니다`는 접두사를 포함한 완전한 서술 key, `별롭니다`·`합니당`형은
   검증된 전체 활용형으로 처리한다. bare `비리`, `별`이나 일반 POS 통합은 허용하지 않는다.

|---|---:|---:|---:|---:|
| Accuracy | 60.35% | 60.44% | 60.61% | +0.26%p |
| Macro F1 | 0.696756 | 0.697070 | 0.698211 | +0.001456 |
| Positive recall | 77.2279% | 77.4090% | 77.6504% | +0.4225%p |
| Negative recall | 43.6667% | 43.6667% | 43.7662% | +0.0994%p |

이는 반복 관찰한 development의 기술 통계이며 독립적인 유의성 검정 결과가 아니다.
특히 negative recall의 개선 폭은 작다. 정확도를 올리기 위한 점수 조정이나
개별 development 오류 문장의 패치는 하지 않았다.

Mining 40,000건의 미매칭 문장은 기준 9,888 → 보강 1의 9,765 → 보강 2의 9,707건이다.
아래는 보강 1 이후와 보강 2 이후의 **미매칭 어절** 집계다. 한 어절은 하나의 유형에
속하지만 한 그룹은 여러 유형에 나타날 수 있다. 이는 감성 오답 수가 아니며 중립 어휘와
의도적으로 차단한 복합명사도 포함한다. 집계 순서는 파생 접사, 뒤 명사·접미사,
앞 명사·접두사, POS 차이, NA, 기존 key 없음 순이다.

| 유형 | 어절 수: 보강 1 → 2 | 독립 그룹 수: 보강 1 → 2 |
|---|---:|---:|
| 기존 어휘 key 없음 | 263,379 → 263,362 | 37,140 → 37,138 |
| 통째로 NA 분석 | 12,635 → 12,635 | 9,917 → 9,917 |
| 기존 형태소와 POS가 다름 | 1,059 → 970 | 989 → 919 |

| 앞 명사·접두사 경계에서 차단 | 464 → 431 | 448 → 416 |
| 파생 접사 앞의 불완전 key | 113 → 113 | 109 → 109 |

`너무`, `잘` 같은 비감성어, 자모·이모티콘, `속`·`신다` 등의 중의어가 큰 비중을 차지해
이 수치를 모두 복구 가능한 감성 누락으로 해석할 수 없다. `옷이뻐요` 같은 NA 어절은
임의로 쪼개지 않았다. `만족도`는 KOMORAN이 `만족+도/JX`로 분석해 여전히 평가가
나오는 한계가 있다. 경계 반례에는 실제 명사 연쇄로 분석되는 `만족지수`를 사용했다.
최초 보강 후 추가 개선은 위 두 원인에 한정했으며 형태소 어댑터와 부정·강조 문법은 유지했다.

새 mining 보고서 경로·해시·유형별 빈도와 대응 compiled 해시는
[측정 기록](engine-m2-development-results.json)의 `mining_matching_audit`에 있다.
개별 활용형의 의미·POS 근거와 제외 결정은 사전 annotations/provenance에 보존했다.

## 3차 어휘 확장 당시의 오류 표본 감사

A~F 버킷마다 seed 20260906으로 최대 50개 ID를 고정 추출했다. 부정 재현율 병목에
맞춰 3차 측정의 A(negative→미매칭 중립) 50건과 C(negative→positive) 50건을
사후 감사했다. 이 진단을 사전 극성이나 개별 문장 규칙의 근거로 사용하지 않았다.
B/D/E/F 표본은 측정 기록에 보존했으며 여기서는 수동 원인 분류를 하지 않았다.

| 버킷 | 전체 건수 | 감사 표본에서 관찰한 가능한 원인 |
|---|---:|---|
| A: negative→미매칭 중립 | 1,717 | 형태소 미인식 24/50, 다의성 19/50, 부정 범위 11/50, 어휘 누락 7/50 |
| B: positive→미매칭 중립 | 774 | 표본 ID 보존 |
| C: negative→positive | 858 | 혼합 평가 30/50, 평점 노이즈 가능성 13/50, 가정·부정 범위 각 10/50 |
| D: positive→negative | 103 | 표본 ID 보존 |
| E: 상쇄 | 282 | 표본 ID 보존 |
| F: 분석 오류 | 231 | 표본 ID 보존 |

한 문장에 복수 원인이 가능하다. 이는 AI의 진단 가설이며 라벨 오류가 확인됐다는 뜻은
아니다. 행별 분류는 [오류 감사 기록](engine-m2-error-audit.json)에 있다.
형태소 미인식에는 NA/잘못된 분절도 포함하며 실행 실패인 F와 구별한다.
혼합 평가·가정·상태 변화와 중립적 묘사를 사전만으로 해결하려면 잘못된 일반화가 생긴다.
이번 변경에는 문맥 규칙이나 형태소 fallback을 추가하지 않았다.

## 검증과 재현

현재 변경으로 Python 3.12.3에서 전체 **564개 테스트 통과**, Python 3.10.20에서 관련
사전·매칭·컴파일러 **152개 테스트 통과**. 매칭 보강 1의 전체 테스트는 540개 통과였다.
기존 추출·합성 fixture·문법·v1/v2 테스트를 유지했다.
구어·활용·원문 span, 수정어 on/off 사건 동일성, 중의어 반례, 컴파일 재현성,
라벨 없는 입력 계약, workset 그룹 분리와 holdout 파일 접근 차단을 검증했다.

환경은 JDK 17.0.20.1, KoNLPy 0.6.0, JPype1 1.6.0이다. 실제 모델·JAR·JVM 해시는
측정 기록의 runtime에 있다. 저장소 루트에서 설치된 환경의 Python으로 실행한다.
출력 디렉터리와 mining 보고서 파일은 기존 결과를 덮어쓰지 않도록 새 경로여야 한다.

```bash
python -m scripts.prepare_sentiment_workset_v2 \
  --old-benchmark artifacts/benchmark/v1 \
  --output artifacts/benchmark/m2-workset-repro
python -m scripts.mine_sentiment_coverage \
  --inputs artifacts/benchmark/m2-workset-repro/mining.inputs.jsonl \
  --assignments artifacts/benchmark/m2-workset-repro/assignments.jsonl \
  --output artifacts/benchmark/m2-workset-repro/coverage.json
python scripts/build_sentiment_lexicon.py
python -m pytest -q
python -m scripts.run_m2_development \
  --workset artifacts/benchmark/m2-workset-repro \
  --output artifacts/benchmark/m2-development-repro
```

현재 사전으로 재현한 mining coverage는 과거 M/batch2 보고서와 다를 수 있다.
과거 측정은 각 `artifacts/benchmark/m2-development-*/candidate/` 스냅샷에 대응한다.
이 문서는 개발 결과만 확정한다. 후속 독립 최종 결과는 별도 final 문서로 보고한다.
