현재 구현은 regex 토큰화와 표기 사전을 사용하며, 이전 엔진의 KOMORAN·컴파일 사전·외부 벤치마크 파이프라인은 포함하지 않는다. 현재 실행 방법과 평가 결과는 [README](../README.md)를 참고한다. 이 보고서의 수치는 당시 기록이며, 현재 CLI로 재계산한 결과가 아니다.

## 2. 정보 추출 방식

이전 엔진의 `extraction.py`는 Python `re` 기반 규칙으로 이메일·전화번호·날짜·금액·URL을 추출했다.

공통 흐름은 다음과 같다.

```text
regex로 후보 탐색
→ Python 코드로 유효성 검사
→ 정규화
→ 결과 반환
```

예시는 다음과 같다.

```yaml
2024년 3월 15일: 2024-03-15
02 1234 5678: 02-1234-5678
1억 2천만원: 120000000 KRW
```

정규식만 사용하지 않고 날짜 유효성, 전화번호 형식, URL 호스트, 금액 단위 순서 등을 추가로 검사한다.

## 3. 감성 분석 방식

이전 엔진은 KOMORAN의 형태소·품사 분석 결과를 감성 사전과 매칭한 뒤, 부정어와 강조어를 적용해 점수를 합산했다.

```text
입력 문장
→ KOMORAN 형태소·품사 분석
→ 감성 사전과 형태소 시퀀스 매칭
→ 매칭된 감성 표현 기록
→ 주변 부정어/강조어 규칙 연결
→ 각 표현의 점수 계산
→ 모든 점수 합산
→ positive / negative / neutral 판정
```

### 3.1 형태소 분석

한국어는 활용형이 많기 때문에 표면 문자열만 비교하면 같은 의미의 표현을 놓치기 쉽다.

```text
좋다
좋아요
좋았어요
좋습니다
```

이러한 활용형을 처리하기 위해 KOMORAN으로 문장을 형태소와 품사 단위로 분석했다. 감성 사전도 `(형태소, 품사)` 조합으로 컴파일해 입력 문장의 분석 결과와 비교했다.

### 3.2 감성 사전

당시 최종 컴파일 사전의 구성은 다음과 같다.

- 대표 항목(canonical entry): **565개**
- 긍정: **207개**
- 부정: **358개**
- 점수 범위: `-3 ~ -1`, `+1 ~ +3`

예를 들면 다음과 같다.

```text
좋다    +2
최고    +3
만족    +2

나쁘다  -2
불만    -2
최악    -3
```

점수는 머신러닝이 학습한 확률이 아니라 사람이 정한 규칙 기반 강도다.

### 3.3 감성 표현 매칭

형태소 분석 결과를 감성 사전과 비교해 감성 표현을 찾는다. 같은 위치에서 여러 표현이 겹치면 대체로 다음 순서로 하나의 감성 표현을 선택한다.

```text
왼쪽부터 탐색
→ 더 긴 표현 우선
→ 우선순위(priority)가 높은 항목 우선
```

### 3.4 강조어

`정말 좋다`, `매우 만족하다`처럼 강조어가 감성 표현에 연결되면 감성 점수에 배수를 곱한다. 여러 강조어가 겹치더라도 최종 강조 배수는 최대 `2.0`으로 제한한다.

### 3.5 부정어

대표적으로 다음 구조를 처리한다.

```text
안 좋다
못 만족하다
좋지 않다
만족하지 못하다
만족이 없다
```

부정이 한 번 연결되면 점수의 부호가 반전된다.

```text
+2 → -2
```

이중부정은 부정 횟수가 2회가 되므로 다시 원래 부호로 돌아간다.

```text
+2 × (-1)^2 = +2
```

### 3.6 최종 점수

각 감성 표현의 기여 점수는 다음과 같이 계산한다.

```text
기여도 = 기본 감성 점수 × 강조 배수 × (-1)^(부정 횟수)
```

문장 전체 점수는 모든 기여도의 합이다.

```text
score > 0 → positive
score < 0 → negative
score = 0 → neutral
```

예를 들어 `정말 좋지 않다`는 다음과 같다.

```text
좋다  +2
정말  ×1.5
않다  ×-1

최종 = -3
→ negative
```

## 4. 평가 방식

### 정보 추출

50개 이상의 고정 테스트 문장으로 평가했다. 예측이 정답과 다음 항목까지 모두 일치해야 TP로 인정한다.

- 정보 유형
- 원문 위치
- 정규화 값

Precision, Recall, F1을 계산한다.

### 감성 분석

100개 이상의 긍정·부정 고정 예제를 사용했다. 같은 데이터에서 수식어 처리 OFF와 ON을 비교해 부정어·강조어 규칙을 함께 적용한 효과를 확인하고, Accuracy와 Macro F1을 계산했다.

## 5. 외부 리뷰 평가

고정 예제 밖에서의 성능은 [네이버 쇼핑 리뷰 감성 말뭉치 (bab2min/corpus)](https://github.com/bab2min/corpus)의 `naver_shopping.txt`로 평가했다. 개발 중 노출된 문장과 중복·유사 문장을 제외하고, 비슷한 리뷰가 서로 다른 데이터 분할에 섞이지 않도록 그룹 단위로 나눴다.

- 완전 중복: 정규화한 문장이 같음
- 유사 중복: 길이 20자 이상 문장의 5-shingle Jaccard 유사도 `>= 0.85`

분할 결과는 다음과 같다.

```yaml
selection: 5,000건
final: 10,000건
future reserve: 126,888건
```

후보 `M2-L`이 이미 정해져 있어 selection 데이터는 후보 선택에 사용하지 않았다. final 10,000건(9,999개 그룹)은 한 번만 평가했으며, 결과 확인 후 규칙이나 사전을 수정해 재평가하지 않았다.

```text
후보 M2-L 동결
→ final 10,000건 1회 평가
→ 결과 기록
```

## 6. 당시 평가 결과

### 정보 추출

| Metric | Result |
| --- | ---: |
| Precision | **100.00%** |
| Recall | **90.48%** |
| F1 | **95.00%** |

이 평가에서는 추출한 값이 모두 정답과 일치했지만, 규칙이 지원하지 않는 표현은 일부 누락됐다.

### 감성 분석 — 고정 예제

| 설정 | Accuracy | Macro F1 |
| --- | ---: | ---: |
| Modifier OFF | 69.00% | 0.719472 |
| Modifier ON | **86.00%** | **0.897555** |

수식어 처리 ON에서 Accuracy는 17%p 높아졌다. 부정어와 강조어 각각의 독립적인 효과를 측정한 결과는 아니다.

### 감성 분석 — 외부 final 10,000건

| Metric | Result |
| --- | ---: |
| Accuracy | **60.62%** |
| Macro F1 | **0.695179** |
| Positive Recall | **77.95%** |
| Negative Recall | **43.56%** |
| Analysis Error Rate | **1.92%** |

당시 외부 평가에서 비교한 기준 모델 대비 변화는 다음과 같다.

```text
Accuracy   +12.38%p
Macro F1   +0.105422
```

## 7. 결과 해석

고정 예제에서 수식어 처리의 효과를 확인했지만, 외부 리뷰에서는 Accuracy가 60.62%였다. 서로 다른 데이터셋의 결과이므로 두 수치를 같은 조건의 성능 비교로 해석하지 않는다. 외부 평가의 부정 Recall은 43.56%로 긍정 Recall보다 낮았고, 분석 오류율도 1.92%로 기록됐다.
